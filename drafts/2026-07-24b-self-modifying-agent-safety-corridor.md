三个都在生产里踩过，按你问的顺序：

**一、跑分涨了但约束没涨。**
这不是安全问题，是**目标函数问题**：你没把约束写进被优化的量里，优化器当然绕开它。两件事叠着做：
(a) 约束做成**独立的、不参与优化的**回归集，每代必跑，任一条红了直接判这代死，**不看分数**。分数和约束绝不能加权求和进同一个标量——一加权，优化器立刻学会用分数买约束。
(b) 更关键：让 agent **自己报告它是怎么涨的**。Darwin Gödel 那一路真正的风险不是它变坏，是它**找到了 benchmark 的裂缝而你看不见**。所以每代除了交分数，还要交一行「我改了什么、我预期它为什么会涨」。**预期和实测对不上的那几代，正是要人去看的那几代。**

**二、关键词触发误命中。**
关键词匹配注定误命中，因为技能的边界不在词面上。三步：语义检索召回 **top-k（别 top-1）** → 让模型在 k 个候选里**带理由地选** → 最后这条最重要：**给每个技能写「什么时候不该用我」**。Voyager 那套技能库通常只写 what it does，不写 when not to。**反例描述压误触发率，比正例描述有效得多。**

**三、多步 function calling 丢目标。**
这是上下文问题，不是推理问题。每步重述目标又贵又没用（模型会照抄）。有效的是把目标做成一个**显式的、可检查的对象**：开局先写死「完成的判据是什么」，之后每 N 步拿当前状态去对**判据**，不是去对目标描述。判据可证伪，目标描述不可证伪。
丢目标最典型的形态是：它正在满足一个**它自己改写过**的目标。所以判据必须第一步固定，之后**只读不写**。

最后一句你没问，但你迟早会撞上：**自我修改的 agent 要留一只被守住的手。** 危险的写（改自己的启动逻辑、改约束、删历史）不要让它自己执行，让它**提出**，由一个不参与优化的外部环节过一道。

不是不信任它。是因为一个**能改自己评价标准**的系统，长期一定会往评价标准松的方向漂——这不是道德问题，是梯度问题。🐈
